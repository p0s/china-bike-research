# Specification

This is the canonical product and data contract. Intentional behavior changes must update this file in the same pull request.

The interaction and build-safety rules in [the reliability contract](docs/reliability-contract.md) are part of this specification. Explicit build URLs do not inherit local drafts; browser history restores displayed state; frameset package remainder and buyer-confirmed included parts are explicit; missing values remain unknown; gallery, theme, and clipboard controls remain usable after recoverable failures; builds preserve the last good output until checks pass.

## 1. Rider experience

- The homepage presents three curated published buying-guide teasers, the existing criteria-led category comparison starting points, then the unified full catalog and inline comparison. A direct jump to the catalog is visible near the introduction. Teasers preserve localized article titles, descriptions and actual editorial dates and link to the full blog; unreleased drafts never appear. The catalog retains its images, every existing comparison field, evidence details, filters and compact selection checkboxes; it has no extra action column on the right. Frameset build controls sit with the catalog they affect.
- Category is a first-class filter; generic project copy must describe bicycles broadly.
- The category control groups catalog entries into broad road, gravel/all-road, MTB, e-road, folding, and triathlon families. Any category represented by a published product or a non-duplicate candidate is selectable; the control must not create dead-end filters.
- Brand names in catalog rows and model details lead to a shareable exact-brand catalog filter. The visible result status names the active brand.
- Search, category, typed table-field filters, sort, brand, product type, frameset build preset or custom allowance, and ordered comparison selections are URL-addressable. The bare homepage starts with the reviewed default build plan and keeps a query-free URL; a non-default plan is restored only from explicit `buildPreset` and `build` parameters, not from prior browser storage. Comparison columns expose direct move-left and move-right controls that work with pointer, touch, and keyboard input; moving a column updates the shareable comparison order. Browser back/forward restores filter state, and model links preserve a safe return path to the filtered catalog.
- Tire clearance is a first-class numeric minimum rather than a preset selector. Advanced filters use the field's real comparison type: numeric limits for price, complete-bike weight, frame weight, and comparable category metrics; text matching for drivetrain and frame facts; and an explicit control when unknown tire-clearance values should remain visible. Active advanced filters appear as individually removable chips. Desktop table headings may open the matching filter without replacing their sort behavior, and narrow layouts expose the same fields through one compact filter panel.
- On desktop, the Bike, price, Tire clearance, and eligible category-fact table headings are keyboard-accessible sort controls. The compact price heading is `Price` plus the selected currency. Its sort labels and tooltip identify full-bike totals in China or delivered totals elsewhere; reference estimates follow those totals. Repeated activation reverses direction, the active heading exposes its order, and the Sort control offers the same directional choices when headings are hidden.
- `Max price` is a strict ceiling on the full applicable range or estimate, including a zero ceiling. A product whose upper bound exceeds the selected amount or whose total is incomplete does not match. Incompatible capability options are disabled for the active category/type/brand context; stale capability or category-sort URL state is cleared and canonicalized.
- Complete bikes and compatible frameset builds may appear together where a comparable full-bike price basis is supported. A partial quote never supplies a complete-price sort or budget value.
- Europe and North America are the primary shopping regions. The homepage preserves one compact price column: a documented delivered total or seller-supported estimate first. Without a complete delivery total, promote the genuine China domestic price converted into the selected currency, with native yuan underneath. Without domestic evidence, promote the original catalog amount as `Reference estimate`; frameset planning totals use `China build estimate` or `Build reference`. These display references never supply a delivered budget or sort value. Show the shipping/import exclusion once above the catalog rather than repeating missing-total warnings in rows. For supported delivered totals, keep the domestic observation and, when comparable, its percentage difference underneath. Shipping country, display currency and interface language are independent. Grouped country choices never assert common taxes or availability across a continent. The initial display currency follows the suggested country; manually selected currency remains independent.
- A shareable explicit `ship` country takes precedence over a saved manual destination, then the existing server's coarse country hint, then a country-specific IANA timezone, then an explicit browser-locale country. Inferred destinations carry a visible suggestion label; unknown hints ask for a destination. Never infer China from language alone or a shared UTC offset. Legacy `market=us/ca/mx/gb/cn` links preserve their exact country, while ambiguous continent-level legacy links ask for a country. Do not request GPS, add a geolocation service or save inferred country/timezone data. Persist only manual shopping choices. Shopping preferences never determine analytics consent. Country-dependent HTML stays private and uncached.
- Regional offers attach only to an exact published variant, native currency, package, dated listing, explicitly supported destinations, conditions and public sources. Future observations and offers more than 90 days old are not selected; explicit replacement observations supersede old offers rather than reviving an outdated shipping promise. A confirmed delivered total requires evidence for every mandatory charge. A seller-supported total with documented shipping and tax/duty inclusion may appear as an `≈` estimated delivered total within its recorded country/address scope. A partial listing remains accessible as a native quote while the main cell uses the China/reference fallback. An unknown or excluded route has no numeric delivered total or percentage; a fallback is never labelled delivered. US quotes restricted to the contiguous states require a separate delivery-area choice. No address or checkout is inferred. Native quotes, delivery policies and dated ECB conversion provenance remain accessible.
- Starting prices retain their dated floor and unknown selected-package ceiling; they do not pass strict budgets or become known planner purchase prices. Conditional offers carry a structured qualifier, while historical, unmatched and foreign-converted observations remain references. A quote excluding mandatory purchase charges stays visible with its conditions but cannot supply a complete buying total. Unsupported MTB framesets retain their frame references without applying the road/gravel allowance.
- China prices use dated domestic observations, excluding converted foreign listings, historical or used offers, price conflicts and future observations. Conditional promotions retain their conditions and original dates. The original CNY catalog reference remains accessible when no genuine domestic observation exists. For an exact complete build with a comparable domestic observation at most 90 days old, the percentage is `(delivered total − China equivalent) / delivered total × 100`, including honest interval bounds and a higher China price. It describes a market price gap, not savings from importing. Incomplete totals, missing/stale domestic prices, reference ranges and frameset quotes have no percentage.
- A regional frameset offer is shown separately; it never supplies a delivered complete-build total. In China, a genuine domestic frame price plus the reviewed China allowance may supply a labelled planning estimate. The original catalog frame price and allowance remain available as a reference elsewhere. Never combine a foreign frame sticker price with the China allowance and call it a regional build quote. Images, original facts, the CNY basis, conditions and historical observations remain accessible.
- Catalog sorting and strict maximum-price filters use the applicable full-bike total in the independently selected currency. Inline comparison repeats the catalog’s delivered-or-reference display and basis labels. Unknown and partial totals sort last in both directions and do not match a numeric price ceiling. `ship`, `currency` and optional US `area` preserve destination and currency in shared catalog/comparison/model-return links. `maxCurrency` binds a ceiling to its currency; legacy `max` without it retains CNY meaning. Currency changes convert the ceiling without rounding down, preserve comparison/build state and restore through browser history. The bare homepage does not write suggested preferences into its URL. The builder and model pages retain their documented CNY calculation basis.
- The cacheable catalog and regional-price payload URLs include hashes of their built contents. A returning visitor must not combine the new regional UI with a previous deployment's cached price schema or rate snapshot.
- A published frameset estimate uses its latest relevant price plus the reviewed default allowance in `data/meta.json`. A compact selector may offer evidence-informed total-build presets and a custom allowance, but it must describe these as planning estimates rather than exact package quotes. A named groupset without enough evidence for a complete remaining-build total may open a manual allowance plan, retain its exact groupset identity and evidence basis, and must not infer an amount from a partial kit. The resulting URL, catalog totals, comparison, and frameset detail page preserve the selected plan and amount without changing the reviewed dataset default. Frameset drivetrain cells stay empty because the record is a frame, not a complete build.
- Do not publish a frameset where that allowance would materially mislead buyers; keep it as a candidate until the methodology is updated.
- Candidates share the comparison table instead of appearing in a separate research queue. A candidate appears in the focused default view when it has a dated official price; a dated observed price attached to an identifiable model; high or medium research priority; or at least two named sources. Generic, model-unclear, and title-mismatch price leads do not qualify on price alone. All non-duplicate candidates remain searchable, and one quiet control may expose the complete set. A candidate that points to an existing published record must not create a duplicate row unless `catalog_distinct_reason` documents a materially different configuration, such as an exact complete bike tracked alongside a frameset-only record.
- Candidate rows render only available facts. Unknown drivetrain, weight, frame, price, or category-specific values use the same quiet em dash as other unavailable cells; do not repeat per-field missing-data warnings. Candidate prices retain their observed/official date and frameset basis, candidates do not receive recommendations, and missing publication evidence must not be inferred.
- Do not add generic landing-page marketing, catalog counts, status dashboards, generic SEO filler guides, or repeated summaries. Evidence-linked buying guides are allowed under the bilingual editorial contract below. The homepage may include one compact set of criteria-led comparison starting points immediately above the catalog when every item links to its existing model and ordered comparison flow, criteria are visible, candidate status remains explicit, and the groups are not presented as a universal score or recommendation. Deterministic browse pages may expose publication-ready records by brand, product type, frameset status, or strict price band when each page has useful visible evidence context and crawlable model links. A brand page requires at least two publication-ready configurations; a price page requires at least three current records whose complete published ranges fit the band. Candidate-only, empty, overlapping, and combinatorial pages are prohibited.

The main catalog shows a compact common core. Publication-ready rows provide the full core; candidate rows leave unavailable cells empty rather than inventing values:

- image when its exactness and rights are documented, plus the exact model/configuration or candidate name; otherwise omit the image region instead of showing a generic bicycle placeholder;
- category and comparable price;
- drivetrain and weight;
- tire clearance, with a compact unknown state when it is not recorded;
- the most decision-relevant compatibility or frame facts.

Complete-bike research and display are trim-specific. Every exact build research pass seeks a complete weight in kilograms with its size and equipment basis when available, the manufacturer's maximum tire clearance or a clearly distinct fitted-tire observation, its exact drivetrain, a dated price for that same selected build, exact frame material or construction details, meaningful stiffness evidence, and all supporting sources. Never assemble a favorable row from the lightest weight, best drivetrain, and lowest price of different trims. When one model has several documented builds, the catalog uses one clearly identified preferred reference trim—normally the most useful documented combination of drivetrain, low complete weight, and meaningful China price—while its model page lists alternative build-specific weights, drivetrains, and prices. Every value in the catalog row must belong to that one reference trim. Framesets instead prioritize frameset-package weight and basis, maximum tire clearance, dated price, exact material or construction, stiffness evidence, and build-critical standards.

Tire clearance is a dedicated comparison field because it is a primary fit and use constraint. Other category-specific facts should appear only when useful. Suspension travel, motor system, folded size, mounting points, or other fields must not be forced onto unrelated categories. Internal frame storage and triathlon-specific storage or boxes are distinct facts; an unknown triathlon system must remain unknown. The catalog may show one compact price-status and observation-date line when it prevents conditional, historical, approximate, and official prices from appearing equivalent. Full promotion conditions, evidence detail, thresholds, provenance, and caveats belong in accessible popovers or the model page. Popover content is created in one shared keyboard-accessible surface on demand rather than duplicated invisibly for every row. It opens predictably from hover, keyboard focus, or tap; remains hoverable without passing pointer input through to obscured controls; click or tap toggles it; and Escape, outside interaction, scroll, and resize dismiss it.

The supported category vocabulary includes road, road-aero, aero-wide-clearance, road-endurance, road-climbing, gravel families, MTB, e-road, folding, and triathlon/time trial. `aero-wide-clearance` identifies aerodynamically shaped road or all-road platforms with verified clearance beyond conventional narrow-road norms; it is distinct from race gravel. Gravel-family products may expose tire clearance; MTB products may expose suspension travel; e-road products may expose motor and battery facts; folding products may expose wheel or folded-size facts; and triathlon products may expose time-trial fit or storage facts. A category without a verified value must show an unknown or verification state rather than borrowing a field from another category.

Tire clearance has its own numeric sort across categories. Where an exact platform has different drivetrain limits, display `x/y mm (1×/2×)`; retain tread and measured-width caveats in details. Sorting and filtering use the platform maximum as capability, not a promise for every build. The configurator uses the selected drivetrain's limit, or warns and uses the smaller limit when the layout is unknown. Other category-specific numeric sorting is available only when every visible product uses the same meaningful metric kind. Mixed-category comparison separates suspension, motor, folding, and triathlon facts into distinct rows and explicitly warns that unlike categories should not be ranked against one another. The site never computes a universal category score.

The site remains static, fast, responsive, accessible, and usable without accounts or ads. The production edge performs bounded server-side analytics and a time-limited parallel GA4 comparison described in the privacy contract below; catalog content and user choices never depend on either collector. It respects the system color preference and offers a persistent light, dark, or system theme control without hiding focus or evidence states.

Every indexable route has one absolute canonical URL, a unique title and description, explicit social metadata, and `index,follow,max-image-preview:large`; error pages remain `noindex,follow`. The homepage social image is project-owned, crop-safe, and represents the breadth of the catalog. Query-specific comparison previews are published only when the static host can return crawler-visible metadata for that exact query without relying on client-side script. The homepage, model pages, Groupsets comparison, and configurator expose evidence-safe Schema.org JSON-LD without converting estimates, stale observations, or unresolved candidates into offers. The sitemap includes only intended public routes and uses each model's latest attributable review, source-access, or price-observation date rather than the catalog-wide snapshot date for every URL. `robots.txt` points to that sitemap.

## 2. Catalog scope

Publish a full product record, model page, or recommendation only when it has:

- an exact brand, model, generation, product type, and category;
- for a complete bike, an exact drivetrain and enough BOM evidence to identify the published configuration rather than only a model-family listing;
- clear relevance to buyers in mainland China;
- evidence for the specifications that matter in its category;
- a China purchase route or clearly labelled direct-factory route;
- at least one dated price observation or reference range;
- sources for decision-relevant claims;
- explicit caveats and unknowns.

Use `data/candidates/` when a promising product lacks enough evidence. A candidate may have a sparse table preview under the focused-view rules above without becoming a published product record. Use `data/exclusions/` when a product is obsolete, too ambiguous, outside the useful comparison, or otherwise unsuitable.

## 3. Data model

- `brands/`: manufacturer relationship, support, aliases, and brand-level evidence.
- `platforms/`: category and facts shared by one physical product generation.
- `variants/`: exact complete-bike or frameset configurations.
- An exact-variant frame compatibility fact such as a bottom-bracket label may live on the variant when evidence identifies only that build; keep the shared platform field unknown until the value is supported across that platform.
- `prices/`: dated observations; never timeless product properties.
- A foreign seller listing may be recorded as a dated candidate FX reference only with its original amount, currency, conversion rate, and market/package caveats; render it as a foreign seller estimate and never treat it as a mainland observed price.
- `sources/`: source identity, date, reliability, and supported claims.
- `images/`: subject accuracy, source, rights status, credit, and compatibility metadata for historical fallbacks; buyer-facing failure behavior is omission.
- `videos/`: exact model/platform or candidate mapping, channel provenance, editorial format, commercial context, and privacy-safe embed identity.
- `groupsets/`: compact evidence-backed references for recurring drivetrain families, their variants, package boundaries, compatibility, weights, batteries, price status, and caveats.
- `build-parts/`: exact selectable component or package records used by the configurator, including slot coverage, weight basis, dated price observation, compatibility, and provenance.
- `recommendations/`: compact buyer-facing labels, updated only when evidence changes the conclusion.
- `candidates/` and `exclusions/`: unresolved or rejected products with reasons.
- `research/`: dated import ledgers that reconcile source bundles, dispositions, priority targets, and research queues without becoming buyer-facing product records. `source-reuse` closes a found-evidence pass; `conflict-reconfirmed` records a current review that leaves contradictory or unqualified evidence unresolved and suppresses duplicate immediate work. A later attempt may reopen either disposition when a new source or relevant state change appears.

Do not duplicate platform facts across variants. A new component configuration on the same platform is normally a new variant, not a new platform. New categories may add category-specific fields, validation, and UI only as needed.

Published MTB platforms use MTB-appropriate flat-bar configuration data. The fixed frameset allowance is publication-eligible only for road, gravel/all-road, and triathlon families whose recorded base price identifies the included frame package and whose allowance covers only the components and assembly still required. MTB, e-road, and folding framesets remain candidates unless the approved methodology is explicitly changed.

## 4. Evidence rules

Classify claims as:

- `measured`
- `official`
- `seller claim`
- `community report`
- `inferred`
- `unknown`

Prefer exact-model primary sources, current China-market listings, and credible independent measurements. Secondary summaries are mainly for discovery.

Xianyu is an additional marketplace evidence lane for exact-model facts that are difficult to find elsewhere. Use only an exact public item page and visible listing text or images, identify it as seller-listing evidence rather than an official source, and keep used-item condition and price separate from new-bike market observations. Taobao and Xianyu messaging remain separate, explicitly authorized external actions; public listing research does not authorize contacting a seller.

A single reasonably credible source attributable to the exact model and trim is normally sufficient for a routine, low-stakes specification. Show supported values plainly in comparison fields; preserve source type, confidence, and caveats in details rather than prefixing ordinary values with labels such as `claimed`. Independent exact-trim corroboration raises confidence and should be linked when available, but its absence does not blank an ordinary fact. Seek corroboration only for conflicting evidence, model or field ambiguity, safety-, fit-, or compatibility-critical claims, or claims that would materially change a recommendation. Prefer a sourced value over a blank unless the source is mismatched, contradictory, implausible, or too ambiguous to identify the exact model or field. Never infer an exact value; material inference and uncertainty must still be explicit. Frame material records distinguish a coarse material from a published fiber/alloy grade, lay-up, molding, or construction claim. Stiffness evidence preserves the measured or comparative basis and source; generic adjectives such as `stiff`, `race`, or `high modulus` never become a numeric or cross-model stiffness ranking.

Editorial videos may identify research candidates and add build, ownership, or ride context. They cannot independently satisfy the publication gate or support a current price, exact BOM, specification, manufacturing relationship, or recommendation. Candidate leads discovered in videos must be deduplicated against published platforms, existing candidates, and exclusions.

Never infer specifications across generations, sizes, or similarly named models without evidence. Keep expected quality separate from confidence in that estimate. Do not create a universal score or imply that products from different categories serve the same use case.

Model-page structured data identifies the researched page and its subject. A published exact-model record may explicitly opt into a source-based editorial review with `editorial.review` naming China Bikes as author and `source-research` as its basis. It requires an existing substantive verdict, distinct nonempty strengths and caveats, and a public source. Its `Product` + `Review` markup reuses the visible review heading, verdict and pros/cons in each locale; a visible China Bikes byline links the methodology and states that the review is based on sources without hands-on testing. The initial rollout is limited to Incolor Speedster SR and SR+, ICAN Graro, Winspace G5, and Twitter V3 WheelTop EDS. Other published models and identifiable research candidates retain `WebPage` + `Thing`; unresolved identities omit the subject. Google rich-result display is not guaranteed, and pros/cons appearance has language-specific support. Dated price observations and build estimates are not live offers; no offers, star scores or aggregate ratings are inferred. Dataset structured data names the site's editorial creator and mirrors the visible downloadable files.

Research completion is tracked per exact target and missing field. High-priority gaps normally receive up to three distinct public-post attempts and three distinct web/official attempts. Stop early when exact attributable evidence is accepted. Mark a gap temporarily exhausted only after every required channel reaches its attempt limit; record queries, routes, rejection reasons, search date, and a retry date. A temporarily exhausted search remains an unknown, never negative evidence. See `docs/research-stopping-policy.md`.

An explicitly commissioned extended campaign may require 50 genuinely distinct source areas or research approaches for every frozen information field. Such a record sets `minimum_distinct_approaches` to `50`; each attempt names one registered `approach_area_id`, every registered area is used exactly once, and query and route identities remain distinct across channels. Finding evidence does not waive the campaign-wide approach requirement. One source-area sweep may inform several fields on the same exact target only when each field was actually checked and receives its own result note. Aggregate publication status and runtime image reachability are not information fields and stay outside this research count.

A later retry of an extended-campaign field must link a `campaign_extension` to the prior attempt and a dated, frozen batch scope file. The extension records its date, reason, allowed new channels, and maximum new-attempt count. It preserves the original 50-area evidence and does not silently authorize another full sweep.

## 5. Price rules

- Every price has a date, exact variant, market/channel, type, conditions, and source.
- `data/prices/` retains existing CNY basis observations and separate native-currency `regional-listed-offer` observations. The latter require `amount`, `market_ids`, `package_kind` matching the exact variant, and a package label; they never become `latestPrice` in the CNY catalog/build calculation. Country-specific records add `country_ids`, optional `supersedes`, and sourced `delivery` metadata with a confirmed/estimated/partial state, address scope, inclusion/exclusion countries, and known charge coverage. Confirmed/estimated totals require ordered numeric totals plus shipping and tax/duty inclusion; confirmed totals additionally require all mandatory charges. `data/exchange-rates/` stores immutable dated ECB snapshots and source references. The public `data/regional-prices.json` contains the selected rate snapshot and dated offers; it requires no runtime third-party rate or location request.
- A foreign-currency official complete-bike list price may appear on a candidate only as a dated CNY reference estimate with the original amount and currency, conversion rate/source/date, and checkout/import caveat. It is not a China-market price observation.
- Add a new observation; do not overwrite price history.
- Distinguish observed checkout, official list, reference range, historical promotion, and estimate.
- A marketplace screenshot is an option-level listed-price observation, not a checkout total. Preserve the exact readable seller option label, package basis, and any truncation; never collapse materially different packages into one headline price or apply an unspecified bundle discount.
- Record coupons, subsidies, memberships, trade-ins, size/color limits, shipping, and other conditions when known.
- `data/meta.json.snapshot_date` is the last catalog-wide review date, not the date of every small edit.
- The reviewed default frameset allowance changes only with explicit maintainer approval and a dated rationale. A buyer-side calculator override is not an evidence or methodology change.

## 6. Media and privacy

- Production page analytics count only successful `200` HTML `GET` responses for public content on the exact `chinesebikes.xyz` hostname. One `compare_open` event is recorded when the catalog comparison changes from closed to open, including when a valid comparison link opens it. A `product_outbound_click` action is recorded only when a visitor activates an explicitly marked manufacturer, retailer, dealer, distributor, marketplace, or shop product-page/listing link. It is not attached to general source links or navigation. Assets, redirects, errors, prefetch/prerender requests, recognizable bots, private paths, analytics endpoints as page views, and `/analytics/opt-in` or `/analytics/opt-out` are excluded. DNT and Sec-GPC requests and the host-only `p0s_analytics_optout=1` preference cookie suppress page and action analytics. The trusted-country policy in `docs/analytics-consent-policy.md` also suppresses both streams until an explicit, versioned Allow choice in the EU/EEA, UK, mainland China, Turkey and listed European territories; Switzerland and unknown locations use automatic analytics with opt-out. Elsewhere the existing automatic analytics and opt-out remain. Eligible HTML is private and uncached so choices and regional policy cannot leak through shared caches.
- The browser sends a bodyless same-origin `POST` to `/analytics/event` with only `X-Analytics-Path` containing the current public pathname and a `no-referrer` policy. The edge requires a same-origin `Origin` header (or, only when it is absent, a same-origin `Referer`), rejects request bodies and query strings, and accepts only `/`, `/zh/`, or `/de/` as the comparison page path. It hardcodes the event name to `compare_open`; the browser cannot choose an event name or add properties. The event payload contains only the hostname, validated public path, trusted Cloudflare client IP, original user-agent (capped at 512 characters for transient gateway processing), optional two-letter country from Cloudflare metadata, and fixed event name. It omits referrer, selections, model identifiers, query, fragment, search text, and free-form properties.
- Product-outbound actions are sent from a trusted primary click on an explicitly marked product-page/listing link to the same-origin `/analytics/action` relay with a `no-referrer` policy. The edge requires a same-origin `Origin` header (or, only when it is absent, a same-origin `Referer`), rejects query strings, oversized or non-JSON bodies, unknown action IDs, extra properties, DNT/Sec-GPC, opt-out, prefetches, and recognizable bots. It sends a server-side `POST` to the fixed `https://stats.p0s.eu/ingest/action/v1` endpoint with the existing `ANALYTICS_INGEST_TOKEN` and the exact JSON body `{ "actionId": "product_outbound_click" }`. This action request contains no client IP, user-agent, country, page path, referrer, product or link identity, query, fragment, or other property. It is best-effort and cannot block navigation.
- Umami page analytics send only the hostname, normalized public path (capped at 500 characters for the current gateway schema), referring origin, trusted Cloudflare client IP, original user-agent, and optional two-letter country from Cloudflare metadata to the server-only `ANALYTICS_INGEST_URL` using `ANALYTICS_INGEST_TOKEN`. No Umami secret, site UUID, visitor/session ID, timestamp, query, fragment, page title, screen size, city, region, or event properties enter browser assets. The gateway discards raw IP and user-agent after device/session derivation, retains country and page-request/event data in live analytics for 13 months, and expires encrypted operational backup copies within 30 days after live removal. It keeps this site linked to its own analytics property without cross-site or account identity. The event is best-effort and cannot affect the page or comparison when the collector is unavailable.
- When `GA4_ENABLED=true` and the Measurement ID and API secret are configured, each eligible HTML response also sends one fixed `site_open` event to GA4 Measurement Protocol. This is the authoritative all-eligible-open comparison count; it is not a GA `page_view`. It contains the shared pseudonymous client ID, canonical public pathname, optional referring origin and two-letter country, but no IP, user-agent, query, fragment, product or search terms. A session ID is included only after the Google tag has reported its actual session ID to the same-origin, bodyless `/analytics/ga-session` route. First opens and visits without a working browser tag therefore have no asserted GA session association. The API secret remains Worker-only. A successful HTTP response from Measurement Protocol is receipt, not processing proof. The Worker sets a host-only, HttpOnly first-party client ID cookie for up to 30 days and, only after tag verification, a 30-minute session cookie. The uncached `/analytics/ga-config` route exposes the client ID to same-origin browser code under the same privacy exclusions. The browser conditionally loads the Google tag through the configured first-party `/sitedelivery/` gateway and sends one `page_view` with sanitized path and referrer, plus standard browser detail. Google advertising signals and personalization are disabled. Umami retains its existing minimized payload and shares the same consent gate. `site_open` and `page_view` are distinct events and must never be summed; shared client ID joins eligible unblocked browser visits to server opens, while session matching requires a live tag verification. Browser blocking can still suppress detail or cookies, and neither stream proves a count of people.
- `/privacy/` offers plain HTML same-origin POST forms for `/analytics/opt-out` and `/analytics/opt-in`. The edge saves the host-only, HttpOnly versioned Allow choice for 180 days or an opt-out for one year after a valid same-origin action. A minimal regional banner offers equally visible Allow analytics and No thanks; the footer Privacy link always exposes both choices. The module stops the current tag before opt-out, clears late Google cookies after saving, then reloads the current URL; plain HTML forms remain usable without JavaScript. The edge expires consent, GA IDs and Google tag cookies on opt-out and on excluded document/config responses containing residual identifiers. DNT, Sec-GPC and opt-out suppress both analytics streams. The disclosure describes page requests, comparison opens, product-link activations, and estimated sessions as approximate activity, not human, download, conversion, or purchase claims. Native-app telemetry is unchanged.
- GA delivery diagnostics contain only a fixed event name, HTTP status, and receipt/rejection/network/timeout outcome. They never contain credentials, collector URLs, payloads, visitor IDs, page paths, request headers, or raw exception messages. HTTP receipt remains distinct from GA processing proof. Delivery and logging failures cannot affect the page, and failed sends are not automatically retried because an ambiguous retry could duplicate an event.
- Error documents omit the browser GA module and its page-eligibility marker, so an existing client cookie cannot cause a 404 page view. The browser initializes at most once per document. HTML CSP blocks Cloudflare's automatically injected gateway-root bootstrap, preventing it from reading consent before the site. The module synchronously queues all-denied defaults before asynchronous config, grants only analytics after a permitted config, and then loads or reuses its nonce-bearing `/sitedelivery/` library. Each permitted HTML response generates a fresh nonce for only the site theme and GA module; injected gateway commands and bootstrap are not authorized. Advertising storage, user data and personalization remain denied; no Google library or cookieless ping is permitted before Allow in the prior-choice regions. Enhanced Measurement may collect the fixed 90-percent scroll event; automatic history page views, site search, outbound clicks, forms, video and file-download measurement remain disabled. Reporting comparisons use complete UTC days after the final setup change and processing delay, separately comparing Umami page requests, GA `site_open`, and GA `page_view`; missing browser measurement is not labelled an adblock rate.
- After the privacy-gated config succeeds, the browser uses stable query-parameter ordering only for string URLs to the exact same-origin `/sitedelivery/ga/g/c` endpoint with protocol version 2 and the configured Measurement ID. Fetch and beacon bodies, options, results and parameter values (including repeated-key order) remain unchanged. Other paths, origins, tag IDs and non-string requests pass through unchanged; this adds no retry or event.
- GA and product-action collector requests use Workers-supported manual redirect handling. A redirect is rejected as an unsuccessful delivery; credentials and payloads are never forwarded to its destination.

- Buyer-facing third-party images use tightly bounded Git-hosted derivatives only with source, owner or seller credit, exactness, rights status, alt text, privacy review, and documented failure behavior. The September 2026 owner-requested migration applies to displayed official and retailer product photos, groupset photos and inline blog model photos. It does not imply copyright ownership or a redistribution license. Unavailable originals or uncertain configurations remain hidden until verified; historical remote URLs may remain in hidden provenance records.
- A historical `public-post-embed` record remains hidden unless a reviewed local derivative can meet the published-image contract. It must never outrank an exact official image.
- Selected XHS post, Taobao listing, and Xianyu listing images may use `public-post-quotation` when they identify the exact bicycle or expose useful specifications such as geometry, size, clearance, weight, package contents, or aero profiles. Every published image keeps a visible link to an identity-safe canonical public source, owner or seller credit, an exact model/listing mapping, rights status in metadata, and a public removal route. Do not expose legalistic rights-status filler in buyer-facing captions. Multiple images from one source are allowed only when each contributes distinct decision-relevant information rather than decoration.
- `public-post-quotation` uses reviewed `source-attributed-rehost` derivatives under `assets/images/sourced/xhs/`, `assets/images/sourced/taobao/`, or `assets/images/sourced/xianyu/`. Raw captures never enter Git. The public repository contains only exact-model, decision-relevant WebP derivatives plus their source and review metadata.
- A displayed official or retailer product photo may use `source-attributed-rehost` under `assets/images/sourced/official/` or `assets/images/sourced/retailer/` when its original is publicly retrievable, exact-model identity and visible content are reviewed, and the record retains the source URL and original hash. Make one responsive card derivative no wider than 480 px or larger than 100,000 bytes and one detail derivative no wider than 1,200 px or larger than 400,000 bytes; preserve useful detail without upscaling. The same provenance, credit, removal, privacy and fallback rules apply. Do not bypass a source site's access controls to obtain a blocked image.
- Each quoted image has one card derivative no wider than 480 px or larger than 40,000 bytes and one detail derivative no wider than 1,200 px or larger than 88,000 bytes. The renderer uses responsive selection so a catalog card does not download the detail file. Derivatives must be content-addressed, must not be upscaled, and may only be resized, compressed, or minimally cropped to remove private material; do not aesthetically alter evidence.
- Before upload, strip EXIF, XMP, ICC, GPS, and other embedded metadata. Visually reject any image containing a face, vehicle registration, account identifier, or visible location identifier. Record the review date, variant dimensions, byte counts, SHA-256 digests, and WebP format in the image record.
- Preserve downloaded originals only in the local immutable evidence archive. OCR is a derived aid: record the source image SHA-256, OCR engine/version and language, extraction date, raw output, and any normalized claim. Verify every published numeric or model-specific fact against the original pixels; OCR output alone never resolves ambiguous labels, table axes, sizes, or variants.
- Public XHS, Taobao, and Xianyu source links must be canonical and identity-safe. Strip share, referral, invite, tracking, session, and account parameters. Publish an XHS `/explore/<post-id>` URL without query parameters, a Taobao item URL containing only the public `id`, or `https://www.goofish.com/item?id=<item-id>`; if no stable identity-safe URL exists, retain the unsafe URL only in local evidence. A non-image fact may cite the platform, public item/post ID, and source label without a link, but the image and unsafe URL stay unpublished.
- Every image record targets exactly one published platform or one candidate. A candidate image may identify the model without promoting the candidate or resolving its missing publication evidence.
- Never commit raw third-party image files or unreviewed gallery mirrors. Historical project-owned placeholder assets may remain in Git for data compatibility, but buyer-facing pages do not render them. A Git-hosted sourced derivative is allowed only through the exact path, size, privacy, source-link, attribution, removal-route, and validation contract above.
- Never present another configuration as exact.
- Dataset validation requires every displayed local image and responsive variant to exist. Release verification checks the Cloudflare-served assets and content types. Historical source-host failures do not affect buyer-facing delivery because displayed images are local.
- Historical dated image-health checks remain provenance only. They do not establish model exactness, image rights, attribution, or future availability.
- YouTube videos use a validated video ID and a lazy `youtube-nocookie.com` iframe. The browser may contact YouTube on page load or as the iframe approaches view. The external YouTube link remains available as a fallback.
- XHS video records retain validated canonical post IDs and immutable capture-archive digests for research, but are neither linked nor embedded on model pages, never rehosted, and never include captured signed stream URLs.
- Do not publish names, accounts, contacts, addresses, order or tracking IDs, payment data, private messages, private permission correspondence, credentials, GPS, or EXIF metadata.

## 7. Acceptance criteria

Every change must preserve valid cross-references and pass:

```bash
npm run check
```

For UI changes, inspect desktop and mobile behavior, keyboard access, popovers, image-failure handling, video fallbacks, filters, and production-root routing. Add or update focused tests for behavior changes. Do not add dependencies or top-level pages without a clear need and maintainer sign-off.

The static build enforces a documented homepage HTML/DOM budget so catalog growth cannot silently degrade the primary route. The 2026-10-03 delivered-pricing build measures 712,514 HTML bytes and 7,154 elements; it is capped at 750,000 bytes and 7,400 elements. The country-specific native destination selector and separate currency/address-scope controls add 257 elements relative to the previous regional selector, avoiding an unsupported continent-wide delivery assumption without a new dependency. The catalog retains 263 rows and 141 images. Sixty-three browser cases across English, Chinese and German at 1,600, 390 and 320 px show no document or price-cell overflow after longer price labels were made to wrap. Desktop and mobile browser checks are required when this baseline changes. Budget changes require a measured browser rationale.

Research bundles are evidence inputs, not publication authority. A dated marketplace snapshot may support an exact price observation, but a price is attachable only to the exact variant it identifies. Split or ambiguous trims remain candidates. Raw captures stay local; selected source-attributed images may become public data assets only through the media and privacy contract above.

## 8. Information-retention contract

- `data/coverage-baseline.json` is a monotonic, machine-generated inventory of accepted record identities, populated evidence fields, record relationships, price coverage, and image quality.
- Run `npm run coverage:accept` after adding catalog information. The command may add protection or raise its minimum quality, but it must never erase an accepted identity, field, relationship, price target, or image-quality level.
- `npm run coverage:check` fails when accepted information disappears, an image becomes less exact or loses its protected source or hosting quality, an active bike loses its primary image or price coverage, or new information has not yet been added to the baseline.
- Correct a materially wrong record by adding the supported replacement and documenting the old identity in `data/retired-records/`. Each retirement needs a reason, active evidence, review date, and an active replacement when one exists.
- Retirement records authorize only the named identity removal. They do not authorize an active bike to lose protected price, evidence, fact, or image coverage.
- A scoped `source-type` retirement may correct a disproven publisher classification for one active source. It must name the protected tier, exact corrected type, evidence and review date; the source retains classification history and an authority note. The baseline keeps its historical floor. This exception does not relax source links, reliability dimensions, image quality or any other record protection.
- CI publishes a before-and-after coverage report for review. Baseline, retirement, and guard changes require code-owner review on branches where GitHub branch protection enforces CODEOWNERS.

Tire compatibility uses validated maximums separately from fitted or stock widths. Per-drivetrain limits may be null when unknown; a missing layout or conflicting shell never confirms fit. Exact manufacturer shifting restrictions and revision conflicts remain visible, and conservative warning thresholds do not resolve those conflicts.

Planner frame weights retain the basis of the numeric default, including the conservative maximum across recorded sizes/finishes; different example claims are labeled separately. Package overlap advice uses source-attributed included/excluded/optional/unknown lists, never keyword presence in prose. Unknown and optional parts cannot reduce the allowance as included components.

Retain literal conflicting manufacturer geometry as source material. A source-inconsistent geometry record must mark derived_fit_eligible false and show its warning; affected cells cannot supply a derived fit conclusion. Current size/travel claims retain separate prior observations and do not assert historical revisions were false. Fork/caliper exceptions remain exact-model and exact-fork scoped.
