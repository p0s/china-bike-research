# Specification

This is the canonical product and data contract. Intentional behavior changes must update this file in the same pull request.

The interaction and build-safety rules in [the reliability contract](docs/reliability-contract.md) are part of this specification. Explicit build URLs do not inherit local drafts; browser history restores displayed state; frameset package remainder and buyer-confirmed included parts are explicit; missing values remain unknown; gallery, theme, and clipboard controls remain usable after recoverable failures; builds preserve the last good output until checks pass.

## 1. Rider experience

- The site name is Chinese Bikes, matching the ChineseBikes.xyz domain (renamed from China Bikes on 2026-10-28). Titles, social and structured metadata, bylines and interface text use it; historical evidence, provenance and generation records keep their original wording. The shared header uses the project-owned red panda riding a drop-bar bicycle from the selected 3B logo direction, with the site name as live text. Browser and Apple touch icons use the same rider on a cream backing. Brand assets are shared across languages and deployment base paths; the home link retains an accessible name.

- The homepage opens directly on the unified catalog and inline comparison. On desktop, a category rail includes criteria-led starting points and refine controls; on narrow screens, category chips and a filter sheet expose the same fields. The Blog remains one header link away and contextual model/article links stay crawlable. No guide teasers or separate curated-card section precede the catalog. Facet/result counts orient the buyer; they are not a catalog-count dashboard. The catalog retains every existing comparison field, evidence detail, exact image, filter and compact selection checkbox. Frame-build and regional price settings share one compact header control.
- Category is a first-class filter; generic project copy must describe bicycles broadly.
- The category control groups catalog entries into broad road, gravel/all-road, MTB, e-road, folding, and triathlon families. Any category represented by a published product or a non-duplicate candidate is selectable; the control must not create dead-end filters.
- Brand names in catalog rows and model details lead to a shareable exact-brand catalog filter. The visible result status names the active brand.
- Catalog search ignores case, accents, punctuation and spacing within names; all typed words must match, in any order. General fuzzy matching accepts one inserted, missing, substituted or transposed letter in alphabetic terms of 4–7 letters, and up to two edits in terms of 8–64 letters. It needs no brand-specific exceptions: `xlabs`, `twittr` and `shiamno` can find X-LAB, Twitter and Shimano. Short terms, Chinese text, numeric model codes and their suffixes remain exact. A one-to-three-letter word followed by a number is one model code (`Gen 2` = `Gen2`, `RS 9` = `RS9`), so a lone digit never matches another generation or model number. Search also covers verified alternate names of the brand, platform, build or research profile. During search the default sort becomes Best match: direct matches first, then close matches by edit count, with the usual publication/price order for ties. Explicit sort choices still apply. Label close matches in each row, preserve all other filters and the buyer's original query in the URL, and keep source names and facts unchanged. Matching runs locally with cached row indexes and query scores; it adds no service, dependency or query telemetry.
- Search, category, typed table-field filters, sort, brand, product type, frameset build preset or custom allowance, catalog view, and ordered comparison selections are URL-addressable. The catalog opens as a photo gallery; `view=table` selects the table and a legacy `view=gallery` link canonicalizes to the bare gallery URL. The gallery re-lays out the same rows rather than duplicating them, so the product set, prices, labels, filters, sort, selection, comparison and Build actions are identical in both views, and Back/Forward and language links keep the chosen view. Gallery cards lead with the reviewed, uncropped product photo and show price, tire clearance, weight, drivetrain and frame facts with the same unknown dash as the table; a product without a verified photo shows no placeholder. A photo-size control (−/+ steps and a slider on wider screens) works like zooming a photo grid: it sets an explicit column count between one column and the largest count whose cards stay at least about 150 px wide (about 104 px on phones), so every step changes the grid. Cards adapt to their own width: the smallest keep the photo, name and shown price, small cards add tire clearance, and large cards show every fact. The size is a per-device convenience stored in browser storage with failure-safe fallbacks; it never enters shared URLs. The bare homepage starts with the reviewed default build plan and keeps a query-free URL; a non-default plan is restored only from explicit `buildPreset` and `build` parameters, not from prior browser storage. Comparison columns expose direct move-left and move-right controls that work with pointer, touch, and keyboard input; moving a column updates the shareable comparison order. Browser back/forward restores filter state, and model links preserve a safe return path to the filtered catalog.
- Tire clearance is a first-class numeric minimum rather than a preset selector. Advanced filters use the field's real comparison type: numeric limits for price, complete-bike weight, frame weight, and comparable category metrics; text matching for drivetrain and frame facts; and an explicit control when unknown tire-clearance values should remain visible. Shifting chips (`shifting=electronic|mechanical`) filter on one structured class per row: published variants use their recorded shifting; research profiles are classified only from an explicit word or an exact system name in their drivetrain record, while offered alternatives, conflicts and unnamed systems stay unknown and match neither chip; framesets are never a drivetrain. Legacy `drivetrain=electronic|mechanical` links map to the class. A shifting subline says `fully wireless` only for systems whose reviewed architecture is fully wireless. Active advanced filters appear as individually removable chips. Desktop table headings may open the matching filter without replacing their sort behavior, and narrow layouts expose the same fields through one compact filter panel.
- On desktop, the Bike, price, Tire clearance, and eligible category-fact table headings are keyboard-accessible sort controls. The compact price heading is `Price` plus the selected currency. Price sorting follows the headline amount each row shows in the selected currency — a delivered total, a converted China price or build estimate, or a labelled reference estimate — using its lower bound first and its upper bound for ties, then name and ID. A conditional or reference amount that a row still shows (for example a coupon price in yuan) sorts by that amount converted only for ordering. Rows without a shown amount stay last in both directions. Repeated activation reverses direction, the active heading exposes its order, and the Sort control offers the same directional choices when headings are hidden.
- `Max price` is a strict ceiling on the full applicable range or estimate, including a zero ceiling. A product whose upper bound exceeds the selected amount or whose total is incomplete does not match. Incompatible capability options are disabled for the active category/type/brand context; stale capability or category-sort URL state is cleared and canonicalized.
- Complete bikes and compatible frameset builds may appear together where a comparable full-bike price basis is supported. A partial quote never supplies a complete-price sort or budget value.
- Europe and North America are the primary shopping regions. The homepage preserves one compact price column: a documented delivered total or seller-supported estimate first. Without a complete delivery total, promote the genuine China domestic price converted into the selected currency, with native yuan underneath. Without domestic evidence, promote the original catalog amount as `Reference estimate`; frameset planning totals use `China build estimate` or `Build reference`. These display references never supply a delivered budget or sort value. Show the shipping/import exclusion once above the catalog rather than repeating missing-total warnings in rows. For supported delivered totals, keep the domestic observation and, when comparable, its percentage difference underneath. Shipping country, display currency and interface language are independent. Grouped country choices never assert common taxes or availability across a continent. The initial display currency follows the suggested country; manually selected currency remains independent.
- A shareable explicit `ship` country takes precedence over a saved manual destination, then the existing server's coarse country hint, then a country-specific IANA timezone, then an explicit browser-locale country. Inferred destinations carry a visible suggestion label; unknown hints ask for a destination. Never infer China from language alone or a shared UTC offset. Legacy `market=us/ca/mx/gb/cn` links preserve their exact country, while ambiguous continent-level legacy links ask for a country. Do not request GPS, add a geolocation service or save inferred country/timezone data. Persist only manual shopping choices. Shopping preferences never determine analytics consent. Country-dependent HTML stays private and uncached.
- Regional offers attach only to an exact published variant, native currency, package, dated listing, explicitly supported destinations, conditions and public sources. Future observations and offers more than 90 days old are not selected; explicit replacement observations supersede old offers rather than reviving an outdated shipping promise. A confirmed delivered total requires evidence for every mandatory charge. A seller-supported total with documented shipping and tax/duty inclusion may appear as an `≈` estimated delivered total within its recorded country/address scope. A partial listing remains accessible as a native quote while the main cell uses the China/reference fallback. An unknown or excluded route has no numeric delivered total or percentage; a fallback is never labelled delivered. US quotes restricted to the contiguous states require a separate delivery-area choice. No address or checkout is inferred. Native quotes, delivery policies and dated ECB conversion provenance remain accessible. Regional-offer and delivery-policy links keep their distinct destinations, at least 24px-high targets and 8px separation.
- Starting prices retain their dated floor and unknown selected-package ceiling; they do not pass strict budgets or become known planner purchase prices. Conditional offers carry a structured qualifier, while historical, unmatched and foreign-converted observations remain references. For published and research bases alike, only a purchase-eligible price becomes a known planner purchase input; any other latest price stays in the planner note with its basis, amount, original currency and date, and the buyer enters the exact quote. A quote excluding mandatory purchase charges stays visible with its conditions but cannot supply a complete buying total. Unsupported MTB framesets retain their frame references without applying the road/gravel allowance.
- China prices use dated domestic observations, excluding converted foreign listings, historical or used offers, price conflicts and future observations. Conditional promotions retain their conditions and original dates. The original CNY catalog reference remains accessible when no genuine domestic observation exists. For an exact complete build with a comparable domestic observation at most 90 days old, the percentage is `(delivered total − China equivalent) / delivered total × 100`, including honest interval bounds and a higher China price. It describes a market price gap, not savings from importing. Incomplete totals, missing/stale domestic prices, reference ranges and frameset quotes have no percentage.
- A regional frameset offer is shown separately; it never supplies a delivered complete-build total. In China, a genuine domestic frame price plus the reviewed China allowance may supply a labelled planning estimate. The original catalog frame price and allowance remain available as a reference elsewhere. Never combine a foreign frame sticker price with the China allowance and call it a regional build quote. Images, original facts, the CNY basis, conditions and historical observations remain accessible.
- Strict maximum-price filters still use the applicable complete full-bike total in the independently selected currency: delivered totals outside China and complete China totals in China. Sorting by the shown amount never turns a reference, partial or starting price into a budget value. The separate China-price sort was retired; legacy `sort=china-asc|china-desc` links map to the ordinary Price sort. The default order is `Complete profiles first`: published records, then partial research profiles, each ordered by shown price. An optional `Complete profiles only` switch (`published=1`) hides partial profiles and explains that they are research leads with missing facts; it does not remove candidate discovery from search. Inline comparison repeats the catalog’s delivered-or-reference display and basis labels. Unknown and partial totals sort last in both directions and do not match a numeric price ceiling. When no row has a delivered total for the selected destination, the empty budget field is disabled and says so instead of silently emptying the list. The focused-list offer counts only hidden partial profiles that match the current filters and disappears when none would. On the catalog the fixed comparison tray follows the result controls in keyboard order. `ship`, `currency` and optional US `area` preserve destination and currency in shared catalog/comparison/model-return links. `maxCurrency` binds a ceiling to its currency; legacy `max` without it retains CNY meaning. Currency changes convert the ceiling without rounding down, preserve comparison/build state and restore through browser history. The bare homepage does not write suggested preferences into its URL. Model pages retain their documented CNY calculation basis; the Build planner keeps its yuan records as the calculation basis and converts them only for display, as described in the configurator contract below.
- The cacheable catalog and regional-price payload URLs include hashes of their built contents. A returning visitor must not combine the new regional UI with a previous deployment's cached price schema or rate snapshot.
- A published frameset estimate uses its latest relevant price plus the reviewed default allowance in `data/meta.json`. A compact selector may offer evidence-informed total-build presets and a custom allowance, but it must describe these as planning estimates rather than exact package quotes. A named groupset without enough evidence for a complete remaining-build total may open a manual allowance plan, retain its exact groupset identity and evidence basis, and must not infer an amount from a partial kit. The resulting URL, catalog totals, comparison, and frameset detail page preserve the selected plan and amount without changing the reviewed dataset default. Frameset drivetrain cells say Frame only without assigning a drivetrain to a frame record.
- Do not publish a frameset where that allowance would materially mislead buyers; keep it as a candidate until the methodology is updated.
- Candidates share the comparison table instead of appearing in a separate research queue. A candidate appears in the focused default view when it has a dated official price; a dated observed price attached to an identifiable model; high or medium research priority; or at least two named sources. Generic, model-unclear, and title-mismatch price leads do not qualify on price alone. All non-duplicate candidates remain searchable, and one quiet control may expose the complete set. A candidate that points to an existing published record must not create a duplicate row unless `catalog_distinct_reason` documents a materially different configuration, such as an exact complete bike tracked alongside a frameset-only record. When two already-public candidate records turn out to describe the same trim, a reciprocal dated `same_identity_as` link with a note keeps both IDs, pages, rows and observations and shows the relationship on both model pages; neither record's prices, weights or sources are merged into the other.
- Candidate rows render only available facts. Unknown drivetrain, weight, frame, price, or category-specific values use the same quiet em dash as other unavailable cells; do not repeat per-field missing-data warnings. Candidate prices retain their observed/official date and frameset basis, candidates do not receive recommendations, and missing publication evidence must not be inferred.
- Do not add generic landing-page marketing, catalog counts, status dashboards, generic SEO filler guides, or repeated summaries. Evidence-linked buying guides are allowed under the bilingual editorial contract below. The homepage may include one compact set of criteria-led comparison starting points in the category rail when every item links to its existing model and ordered comparison flow, criteria are visible, candidate status remains explicit, and the groups are not presented as a universal score or recommendation. Starting points retain the existing ordered selections and visible criteria, state no fixed bike count, and may share a bike that meets each group's criteria. Product images and their qualifications stay in the catalog and comparison; rail presets do not repeat thumbnail galleries. Deterministic browse pages may expose publication-ready records by brand, product type, frameset status, or strict price band when each page has useful visible evidence context and crawlable model links. A brand page requires at least two publication-ready configurations; a price page requires at least three current records whose complete published ranges fit the band. Candidate-only, empty, overlapping, and combinatorial pages are prohibited.

The main catalog shows a compact common core. Publication-ready rows provide the full core; candidate rows leave unavailable cells empty rather than inventing values:

- image when its exactness and rights are documented, plus the exact model/configuration or candidate name; otherwise omit the image region instead of showing a generic bicycle placeholder;
- category and comparable price;
- drivetrain and weight;
- tire clearance, with a compact unknown state when it is not recorded;
- the most decision-relevant compatibility or frame facts.

Catalog photos in table and gallery views, comparison photos, and Start page shortlist photos share the same large, uncropped preview on pointer hover or keyboard focus. One shared, pointer-transparent fixed layer shows the largest reviewed derivative beside the thumbnail (up to about 880 px wide), preferring free space to the right, then the left, and only then overlapping; it always fits the viewport beneath the header. Rows, thumbnails and their link hit areas never change size, so neighbouring facts, source links and image notes stay put and remain accessible. A pointer preview opens only after real pointer movement over the photo, never because rows scrolled under a resting cursor. Pointer previews dismiss on leave and focus previews on blur; Escape, subsequent scrolling and resize dismiss both. Touch taps retain direct model navigation. Comparison previews use the same reviewed detail image and dismiss when the comparison is rebuilt or closed. A thumbnail's image-note button stays in the photo's corner and never covers its centre.

Complete-bike research and display are trim-specific. Every exact build research pass seeks a complete weight in kilograms with its size and equipment basis when available, the manufacturer's maximum tire clearance or a clearly distinct fitted-tire observation, its exact drivetrain, a dated price for that same selected build, exact frame material or construction details, meaningful stiffness evidence, and all supporting sources. Never assemble a favorable row from the lightest weight, best drivetrain, and lowest price of different trims. When one model has several documented builds, the catalog uses one clearly identified preferred reference trim—normally the most useful documented combination of drivetrain, low complete weight, and meaningful China price—while its model page lists alternative build-specific weights, drivetrains, and prices. Every value in the catalog row must belong to that one reference trim. Framesets instead prioritize frameset-package weight and basis, maximum tire clearance, dated price, exact material or construction, stiffness evidence, and build-critical standards.

Tire clearance is a dedicated comparison field because it is a primary fit and use constraint. Other category-specific facts should appear only when useful. Suspension travel, motor system, folded size, mounting points, or other fields must not be forced onto unrelated categories. Internal frame storage and triathlon-specific storage or boxes are distinct facts; an unknown triathlon system must remain unknown. Catalog and comparison price cells show the amount and only its decision-relevant basis or conditions; exact observation dates and the frame/build cost split belong in the price popover and model history. The price itself is the keyboard- and touch-accessible disclosure control, avoiding a separate information icon. Keep historical, partial and starting-price qualifiers visible. Move generic conditional labels, source classification and price age into price details; retain a compact offer/source qualifier and observation date there, with exact terms in the linked model price record. In the China/CNY view, omit repeated China-price and frame/build sublines because the market and estimate basis are already shown. Converted references still identify their China amount; delivered prices remain explicitly labelled. Generic research-stage, recommendation and verification badges do not repeat facts in catalog rows: retain editorial value assessments on model pages and put fit uncertainty beside tire clearance. Full promotion conditions, evidence detail, thresholds, provenance, and caveats belong in accessible popovers or the model page. Popover content is created in one shared keyboard-accessible surface on demand rather than duplicated invisibly for every row. It opens predictably from hover, keyboard focus, or tap; remains hoverable without passing pointer input through to obscured controls; click or tap toggles it; and Escape, outside interaction, scroll, and resize dismiss it.

The supported category vocabulary includes road, road-race, road-aero, aero-wide-clearance, road-endurance, road-climbing, gravel families, MTB, e-road, folding, and triathlon/time trial. `aero-wide-clearance` identifies aerodynamically shaped road or all-road platforms with verified clearance beyond conventional narrow-road norms; it is distinct from race gravel. Gravel-family products may expose tire clearance; MTB products may expose suspension travel; e-road products may expose motor and battery facts; folding products may expose wheel or folded-size facts; and triathlon products may expose time-trial fit or storage facts. A category without a verified value must show an unknown or verification state rather than borrowing a field from another category.

Category memberships (2026-10-27): one catalog row and model page can belong to several categories when evidence supports each one. The first (primary) category keeps the category metric, frame-build allowance rules and type-specific comparison facts. Each additional membership (`additional_categories`) records a concise basis, its sources and a review date. Drop-bar road and gravel families may share memberships; triathlon, MTB, e-road, folding and track memberships stay within their own discipline. Criteria: Aero road needs maker or exact-model evidence that aerodynamics is the frame's headline aim; an aero detail on a frame positioned for climbing, endurance or all-round riding does not qualify. Aero, wide clearance needs documented aero shaping plus a documented maximum tire clearance of at least 35 mm. Road race needs the maker to name or file the model as a race bike, describe race geometry, or document team racing on that exact frame; UCI approval, sprint-stiffness claims, racing size options or team colours alone do not qualify. Endurance road and Climbing road need the maker's endurance/comfort or climbing/lightweight positioning or geometry. All-road needs road-oriented geometry, a documented maximum of at least 35 mm and maker mixed-surface, rough-road or all-road positioning; clearance plus endurance positioning alone does not qualify. Race gravel needs maker gravel-race positioning, Adventure gravel needs maker adventure or bikepacking positioning, Gravel touring needs documented rack mounts or maker touring positioning, and Flat-bar gravel needs a flat bar on a maker gravel frame or build. When a maximum depends on drivetrain, the membership basis names the drivetrain that reaches it. Fitted tire widths, mounts or clearance alone never establish a positioning-based membership, and missing evidence leaves a membership out rather than inferring it; an existing class without supporting evidence stays as a recorded gap unless the maker's own positioning contradicts it. A bike with a specific road or gravel sub-type is not also labelled General road or plain Gravel. Family filters and counts include a bike once when any membership belongs to that family; category filters, search, the geometry nearby-size filter and labels use every membership. Under the Road parent, the plain road category reads General road. A comparison is mixed only when its bikes share no family. The curated Wide-tire aero starting point remains a separate criteria-led shortlist, not the Aero, wide clearance filter.

Catalog disclosures show a compact source/basis summary and a link to full model evidence; they do not copy long source narratives into each row. Full price conditions, tire observations and configurations, frame notes, and editorial caveats remain on model pages. Linked evidence disclosures open on fragment navigation. Comparison editorial assessments and buying checks are one optional section; core numeric fields stay first. Model overviews do not repeat the same weight, tire and price facts in generated headings and paragraphs. Mobile facts use distinct lines; repeated type badges and exact duplicate brand aliases are omitted. Profile coverage is disclosed once beside the result count. Frame weight labels distinguish bare or painted frames only when the recorded default basis explicitly states that finish; later video measurements never relabel the default.

Tire clearance has its own numeric sort across categories. Where an exact platform has different drivetrain limits, label each value with 1× or 2×; label front/rear limits explicitly. Retain tread and measured-width caveats in details. The catalog tire filter offers Any drivetrain, 1× and 2×; `tireLayout=single|double` survives URLs, history and language changes. Filtering and tire sorting use the selected recorded limit. A missing limit stays unknown and matches a numeric minimum only when the buyer explicitly includes unknowns. A known unsupported drivetrain is excluded even when unknown limits are included. Fitted and stock widths never supply a validated maximum. With Any drivetrain, sorting and filtering use the platform maximum as capability, not a promise for every build. The configurator uses the selected drivetrain's limit, or warns and uses the smaller limit when the layout is unknown. Other category-specific numeric sorting is available only when every visible product uses the same meaningful metric kind. Mixed-category comparison separates suspension, motor, folding, and triathlon facts into distinct rows and explicitly warns that unlike categories should not be ranked against one another. The site never computes a universal category score.

The site remains static, fast, responsive, accessible, and usable without accounts or ads. The production edge performs bounded server-side analytics and a time-limited parallel GA4 comparison described in the privacy contract below; catalog content and user choices never depend on either collector. Without an explicit choice, the theme follows the OS and its live changes; the control shows the effective Light or Dark label and icon and toggles only between those two states. Explicit choices persist across reloads and tabs. Legacy system preferences remain automatic; storage failures preserve the current page's explicit choice. Focus and evidence states remain visible.

Production HTTP requests permanently redirect to the same HTTPS path and query before serving content or collecting analytics. Cloudflare Always Use HTTPS covers the asset-first routes; the Worker also guards its own routes, which include every HTML document route so documents share its security headers. Every indexable route has one absolute canonical URL, a unique title and description, explicit social metadata, and `index,follow,max-image-preview:large`; error pages remain `noindex,follow`. The homepage social image is project-owned, crop-safe, and represents the breadth of the catalog. Query-specific comparison previews are published only when the static host can return crawler-visible metadata for that exact query without relying on client-side script. The homepage, model pages, Groupsets comparison, and configurator expose evidence-safe Schema.org JSON-LD without converting estimates, stale observations, or unresolved candidates into offers. The sitemap includes only intended public routes and uses each model's latest attributable review, source-access, or price-observation date rather than the catalog-wide snapshot date for every URL. `robots.txt` points to that sitemap.

Homepage social video (2026-10-28): link previews that play direct media inline, such as Apple Messages, use an MP4 named by `og:video`; HTML player embeds do not play there. Every homepage locale (`/`, `/zh/`, `/de/`, `/es/`, `/ru/`) therefore also publishes one project-made clip as `og:video` and `og:video:secure_url` with type `video/mp4`, width and height, and keeps its `og:image` and `twitter:card` as the fallback. The clip is an 8 s silent, fast-start H.264 file under 2 MB: a code-generated miniature of riders on mountain switchbacks, with no third-party footage or exact-model claim. Near the end the scene dims while the site mascot and the domain ChineseBikes.xyz fade in and hold, and the riders keep moving; the domain is its only text, so one file serves every language. `assets/social-video/home-switchback-signature.provenance.json` records the scene, mascot, timing and output hashes. No other route uses this clip; model and candidate pages keep their YouTube `og:video` rule.

### Multilingual editorial and indexing contract (2026-09-18)

- Prioritize practical buying decisions for Europe and North America, while retaining useful mainland China guides and evidence. English visitor-facing copy says “mainland China,” never “mainland” alone; preserve exact source wording in the evidence records. Domestic observations, export offers and currency conversions must not be conflated. Blog cards and article headers omit audience labels.
- English URLs stay unchanged. Simplified Chinese uses `/zh/` and German uses `/de/` with build-time HTML, self-canonical URLs, reciprocal `en`/`zh-Hans`/`de`/`x-default` links, and a same-page language switch retaining safe query/hash state. Do not force redirects based on language or location. Shared assets and source downloads remain outside the language prefix, including on project-path deployments.
- Translate navigation, common interfaces, core reference pages, published-model verdicts and editorial articles. Chinese and German research profiles have fact-grounded native summaries. German also covers interactive controls, model verdicts, reference pages, article tables and worksheets, image descriptions, and privacy choices; original source titles and detailed source annotations retain their original language with visible disclosure. Official model names, source titles and unreviewed detailed source/price annotations can remain in the original language with visible disclosure; do not invent translations of evidence or claim this is a fully translated research archive.
- Spanish (`/es/`) and Russian (`/ru/`) are interface languages for the core decision tools only: the homepage catalog with inline comparison, Geometry, Build planner, Groupsets, Carbon wheels and the error page. They translate navigation, controls, labels, statuses, tool copy and dynamically inserted interface text, format prices and dates for the locale where the page formats them, and keep self-canonical URLs. Each page lists reciprocal alternates only for the locales that exist for that route; the language menu offers the same set. Model pages, guides, methodology and other routes stay in English, Chinese and German, and links from a Spanish or Russian page lead to the English route. A visible note says that product descriptions and evidence notes stay in English. Interface text formats amounts, decimals and units for the locale (for example 9,9 кг and 6 000 ¥) and uses the language's plural forms. An English model page reached from the Spanish or Russian catalog returns there and says briefly, in that language, that the page is in English, Chinese and German. Spanish and Russian documents run through the Worker for the shared security headers but are not analytics-eligible and add no tracking.
- `/blog/`, `/zh/blog/`, and `/de/blog/` contain substantive decision-oriented articles, not programmatic model/keyword combinations. Each article has matching English, Simplified Chinese, and German versions, matching anchors, a genuine organization byline, dates, linked model/source evidence, clear research limitations and no claim of hands-on testing. Comparison tables read the existing catalog; article publication does not refresh observation dates. Authoring lives in `content/posts/`.
- A bikepacking mount matrix reads exact platform `mount_approval` evidence and requires rear-rack approval, fender approval AND official 700C clearance of at least 50 mm for its documented feature screen. Unknowns and conflicts cannot pass. Carrying limits identify the mounting location, cite their own sources and use null for unknown; they never imply a combined or system-mass allowance. Retain prior observations when correcting unsupported mount labels.
- Blog articles use plain content and links instead of expandable source, price or weight panels. Keep dated prices and material qualifications beside the comparison; detailed conditions, measurement bases and original source access dates remain available in the linked model records.
- Published articles offer curated YouTube videos beside the sections they explain. `content/blog-videos.json` records placements and localized relevance/build-difference notes, reusing catalog video provenance where available. Article-only topic footage has its own channel, date and commercial disclosure, without claiming an exact catalog-platform match. Article players load from `youtube-nocookie.com` only after a localized native button is activated; reserve the player aspect ratio and retain ordinary watch links without JavaScript or when the player fails. Cross-origin iframe failures are not reliably detectable; external watch links remain available without claiming automatic retry. Keep creator titles in their original language, commercial disclosures visible, and no autoplay. Videos do not replace dated model evidence or release scheduled drafts.
- The authorized September 2026 twenty-post series includes Europe and US/Canada purchasing guides, ten distinct brand guides and eight practical ownership/building articles. This explicitly requested series is not constrained by the older domestic/international editorial ratio. Official routes and dated owner accounts remain distinct; a practical brand selection is not a sales or reliability ranking.

Follow `docs/editorial-guidelines.md` and the topic boundaries in `docs/editorial-series-2026-10.md`. Unfinished articles have explicit `publication_status: draft` and remain absent from all public HTML, indexes, related links and sitemaps. Schedule this series only when all 100 articles have completed editorial review. ## 2. Catalog scope

Publish a full product record, model page, or recommendation only when it has:

- an exact brand, model, generation, product type, and category;
- for a complete bike, an exact drivetrain and enough BOM evidence to identify the published configuration rather than only a model-family listing;
- clear relevance to buyers in mainland China;
- evidence for the specifications that matter in its category;
- a China purchase route or clearly labelled direct-factory route;
- at least one dated price observation or reference range;
- sources for decision-relevant claims;
- explicit caveats and unknowns.

Use `data/candidates/` when a promising product lacks enough evidence. A candidate may have a sparse table preview under the focused-view rules above without becoming a published product record. Use `data/exclusions/` when a product is obsolete, too ambiguous, outside the useful comparison, or otherwise unsuitable.

Catalog identity (2026-10-27): paint, colour or finish alone never warrants a separate catalog entry, and catalog titles carry no colour or finish names. Material configuration differences, such as drivetrain, wheels, frame material or package, stay distinct as separate entries or documented builds. One entry may group closely similar model years or generations when each build keeps its own dated price, weight and component evidence; frame identity across years is not assumed. Finish and edition labels stay in source evidence and notes, and marketing names that identify an actual model stay in titles. Verified alternate names (`aliases`, optionally with a one-sentence `alias_note` on the family or build relationship) must appear in the record's own sources or opinion titles and must not name another record; they are searchable and shown as “Also known as” on the catalog row and model page, never as a separate entry.

## 3. Data model

- `brands/`: manufacturer relationship, support, aliases, and brand-level evidence.
- `platforms/`: category and facts shared by one physical product generation.
- `variants/`: exact complete-bike or frameset configurations.
- An exact-variant frame compatibility fact such as a bottom-bracket label may live on the variant when evidence identifies only that build; keep the shared platform field unknown until the value is supported across that platform.
- `prices/`: dated observations; never timeless product properties.
- A foreign seller listing may be recorded as a dated candidate FX reference only with its original amount, currency, conversion rate, and market/package caveats; render it as a foreign seller estimate and never treat it as a mainland observed price.
- `sources/`: source identity, date, reliability, and supported claims. Source URLs and brand websites become links, so validation accepts only `http:` or `https:` schemes.
- `images/`: subject accuracy, source, rights status, credit, and compatibility metadata for historical fallbacks; buyer-facing failure behavior is omission.
- `videos/`: exact model/platform, wheelset or candidate mapping, channel provenance, editorial format, commercial context, and privacy-safe embed identity.
- `opinions/`: one collection per exact platform or candidate with paraphrased first-hand opinions, their sources, relationships and stances, and an optional coverage note.
- `groupsets/`: compact evidence-backed references for recurring drivetrain families, their variants, package boundaries, compatibility, weights, batteries, price status, and caveats.
- `build-parts/`: exact selectable component or package records used by the configurator, including slot coverage, weight basis, dated price observation, compatibility, and provenance.
- `wheelsets/`: exact current carbon wheelsets for the Carbon wheels reference and the planner's wheel slot, with rim, safety-limit, weight, hub, spoke, fit, dated price and source fields. Wheelset and build-part IDs share one namespace.
- `recommendations/`: compact buyer-facing labels, updated only when evidence changes the conclusion.
- `candidates/` and `exclusions/`: unresolved or rejected products with reasons.
- `research/`: dated import ledgers that reconcile source bundles, dispositions, priority targets, and research queues without becoming buyer-facing product records. `source-reuse` closes a found-evidence pass; `conflict-reconfirmed` records a current review that leaves contradictory or unqualified evidence unresolved and suppresses duplicate immediate work. A later attempt may reopen either disposition when a new source or relevant state change appears.

Do not duplicate platform facts across variants. A new component configuration on the same platform is normally a new variant, not a new platform. New categories may add category-specific fields, validation, and UI only as needed.

Published MTB platforms use MTB-appropriate flat-bar configuration data. The fixed frameset allowance is publication-eligible only for road, gravel/all-road, and triathlon families whose recorded base price identifies the included frame package and whose allowance covers only the components and assembly still required. MTB, e-road, and folding framesets remain candidates unless the approved methodology is explicitly changed.

## 4. Evidence rules

Classify claims as:

- `measured`
- `official`
- `seller claim`
- `community report`
- `inferred`
- `unknown`

Prefer exact-model primary sources, current China-market listings, and credible independent measurements. Secondary summaries are mainly for discovery.

Xianyu is an additional marketplace evidence lane for exact-model facts that are difficult to find elsewhere. Use only an exact public item page and visible listing text or images, identify it as seller-listing evidence rather than an official source, and keep used-item condition and price separate from new-bike market observations. Taobao and Xianyu messaging remain separate, explicitly authorized external actions; public listing research does not authorize contacting a seller.

A single reasonably credible source attributable to the exact model and trim is normally sufficient for a routine, low-stakes specification. Show supported values plainly in comparison fields; preserve source type, confidence, and caveats in details rather than prefixing ordinary values with labels such as `claimed`. Independent exact-trim corroboration raises confidence and should be linked when available, but its absence does not blank an ordinary fact. Seek corroboration only for conflicting evidence, model or field ambiguity, safety-, fit-, or compatibility-critical claims, or claims that would materially change a recommendation. Prefer a sourced value over a blank unless the source is mismatched, contradictory, implausible, or too ambiguous to identify the exact model or field. Never infer an exact value; material inference and uncertainty must still be explicit. Frame material records distinguish a coarse material from a published fiber/alloy grade, lay-up, molding, or construction claim. Stiffness evidence preserves the measured or comparative basis and source; generic adjectives such as `stiff`, `race`, or `high modulus` never become a numeric or cross-model stiffness ranking.

Editorial videos may identify research candidates and add build, ownership, or ride context. They cannot independently satisfy the publication gate or support a current price, exact BOM, manufacturer specification, manufacturing relationship, or recommendation. A transcript-checked video of the exact model may support what the creator measured or observed on the build shown: a weighed frame or bike with its size and equipment basis is `measured`, while fit, ride, fault and support reports are `community report` evidence. Such evidence is recorded with the creator, build, timestamp and access date, kept distinct from official values, and never applied to a sibling size, trim or generation without its own evidence. A reviewer's tire-fit observation is recorded as a tire-clearance field report beside the official maximum; it never replaces that maximum or becomes a safety rating. Field reports appear in the clearance popover, model facts, comparison and build planner. Compact labels identify the tested model and drivetrain; measured tire widths stay distinct from untested estimates. A shared-platform report never implies that a sibling model was tested. Where 1×/2× limits differ, a short hint explains that front-derailleur, rim and tire choice affect fit without assigning an unverified cause to a particular review. A reviewer's weigh-in of one exact frame or fork is listed under reviewer-measured weights with its size, equipment basis and video timestamp, beside the claimed weights. A creator repeating a manufacturer claim still needs the primary source. Candidate leads discovered in videos must be deduplicated against published platforms, existing candidates, and exclusions.

Transcript review may use the public transcript panel or the caption track served by the exact video's normal player. Record the actual method and caption kind; a player-caption review also requires a SHA-256 digest of its private identity-checked evidence. An empty panel, title, description or caption-availability label is not a reviewed transcript. Article videos expose the same short reviewed highlights as model videos, while retaining intentional player activation, creator attribution, commercial context and ordinary watch links. Use `workshop-guide` for repair demonstrations and `topic-explainer` for general discussions; their highlights identify general guidance rather than approval of the reader's exact equipment. Topic footage may be an article-only build or review without being added to a model's curated video collection; it retains the same transcript gate and does not establish catalog facts.

Never infer specifications across generations, sizes, or similarly named models without evidence. Keep expected quality separate from confidence in that estimate. Do not create a universal score or imply that products from different categories serve the same use case.

Model-page structured data identifies the researched page and its subject. A published exact-model record may explicitly opt into a source-based editorial review with `editorial.review` naming Chinese Bikes as author and `source-research` as its basis. It requires an existing substantive verdict, distinct nonempty strengths and caveats, and a public source. Its `Product` + `Review` markup reuses the visible review heading, verdict and pros/cons in each locale; a visible Chinese Bikes byline links the methodology and states that the review is based on sources without hands-on testing. The initial rollout is limited to Incolor Speedster SR and SR+, ICAN Graro, Winspace G5, and Twitter V3 WheelTop EDS. Other published models and identifiable research candidates retain `WebPage` + `Thing`; unresolved identities omit the subject. Google rich-result display is not guaranteed, and pros/cons appearance has language-specific support. Dated price observations and build estimates are not live offers; no offers, star scores or aggregate ratings are inferred. Dataset structured data names the site's editorial creator and mirrors the visible downloadable files.

Research completion is tracked per exact target and missing field. High-priority gaps normally receive up to three distinct public-post attempts and three distinct web/official attempts. Stop early when exact attributable evidence is accepted. Mark a gap temporarily exhausted only after every required channel reaches its attempt limit; record queries, routes, rejection reasons, search date, and a retry date. A temporarily exhausted search remains an unknown, never negative evidence. See `docs/research-stopping-policy.md`.

An explicitly commissioned extended campaign may require 50 genuinely distinct source areas or research approaches for every frozen information field. Such a record sets `minimum_distinct_approaches` to `50`; each attempt names one registered `approach_area_id`, every registered area is used exactly once, and query and route identities remain distinct across channels. Finding evidence does not waive the campaign-wide approach requirement. One source-area sweep may inform several fields on the same exact target only when each field was actually checked and receives its own result note. Aggregate publication status and runtime image reachability are not information fields and stay outside this research count.

A later retry of an extended-campaign field must link a `campaign_extension` to the prior attempt and a dated, frozen batch scope file. The extension records its date, reason, allowed new channels, and maximum new-attempt count. It preserves the original 50-area evidence and does not silently authorize another full sweep.

## 5. Price rules

- Every price has a date, exact variant, market/channel, type, conditions, and source.
- `data/prices/` retains existing CNY basis observations and separate native-currency `regional-listed-offer` observations. The latter require `amount`, `market_ids`, `package_kind` matching the exact variant, and a package label; they never become `latestPrice` in the CNY catalog/build calculation. Country-specific records add `country_ids`, optional `supersedes`, and sourced `delivery` metadata with a confirmed/estimated/partial state, address scope, inclusion/exclusion countries, and known charge coverage. Confirmed/estimated totals require ordered numeric totals plus shipping and tax/duty inclusion; confirmed totals additionally require all mandatory charges. `data/exchange-rates/` stores immutable dated ECB snapshots and source references. The public `data/regional-prices.json` contains the selected rate snapshot and dated offers; it requires no runtime third-party rate or location request.
- A foreign-currency official complete-bike list price may appear on a candidate only as a dated CNY reference estimate with the original amount and currency, conversion rate/source/date, and checkout/import caveat. It is not a China-market price observation.
- Add a new observation; do not overwrite price history.
- Distinguish observed checkout, official list, reference range, historical promotion, and estimate.
- A marketplace screenshot is an option-level listed-price observation, not a checkout total. Preserve the exact readable seller option label, package basis, and any truncation; never collapse materially different packages into one headline price or apply an unspecified bundle discount.
- Record coupons, subsidies, memberships, trade-ins, size/color limits, shipping, and other conditions when known.

## 6. Media and privacy

- Production page analytics count successful `200` HTML `GET` responses for public content on the exact `chinesebikes.xyz` hostname. One eligible document request schedules exactly one minimized server Umami page observation. The browser may send at most one `page_engaged` event per document, after at least 10 seconds of visible time and at least one trusted click, keydown, or scroll. This records foreground interaction, not a verified human. The same module may also send at most one passive `page_visible` per document after 10 cumulative visible seconds without any input, and one `bootstrap` stage when it starts on a permitted page; hidden time does not count. `page_visible` is a browser estimate, not a verified human or reader. Assets, redirects, errors, prefetch/prerender requests, recognizable bots, Cloudflare's trusted `verifiedBot` signal when available, private paths, and analytics endpoints as page views are excluded. DNT, Sec-GPC, opt-out, and the trusted-country consent policy suppress analytics before collection. Eligible HTML is private and uncached so choices and regional policy cannot leak through shared caches.
- Comparison opens use a bodyless same-origin POST to `/site-events/action` with only the public catalog pathname in `X-Analytics-Path` and an optional integer `X-Comparison-Count` from 2 to 10. The older `/analytics/event` route remains available for cached assets. The edge rejects bodies, queries, invalid counts, invalid QA signals, and non-catalog paths; it fixes `compare_open` and derives page type and interface language. Both collectors receive the bounded public context. An exact initial document query of `?measurement_qa=1` adds only `qa:true`; browser action and signal requests keep `X-Measurement-QA: 1` from that original navigation when comparison controls update history. With navigation timing available, a normal document does not become QA through a history-only URL change; older environments without that API use the exact current query. No query or run label is forwarded.
- Product-outbound actions use a trusted primary click on a marked product source or catalog listing/offer link and a same-origin JSON POST to `/site-events/action`. The older `/analytics/action` route remains available for cached assets. The browser sends only the fixed action ID and public pathname, with either a public model-source ID on a model page or a public offer ID on `/`, `/zh/` or `/de/`. Delivery-policy, general source and navigation links remain excluded. The edge resolves IDs against the catalog manifest and derives exact public model and brand IDs, destination hostname, source class, interface language and page type. It rejects unknown or mixed IDs, extra properties, queries, fragments and oversized/non-JSON bodies. For an exact QA signal, the edge labels the real action and its context `qa:true`; the collector validates them and stores only its fixed `measurement_qa` diagnostic instead of the customer action, and no customer action is sent to GA.
- Optional action-module loading cannot delay catalog initialization or outgoing navigation. Up to 20 permitted public action contexts may wait in document memory for at most five seconds; each is dispatched once after the module loads, with its original public pathname and current privacy checks. Failure, expiry or document departure discards pending actions without retry or persistence. An immediate opt-out stops both action helpers before its preference request completes, including after a failed save. An outbound click before the module loads may remain unrecorded if navigation occurs first; keepalive applies only after its request starts.
- Umami page analytics send only the hostname, normalized public path (capped at 500 characters for the current gateway schema), referring origin, trusted Cloudflare client IP, original user-agent, and optional two-letter country to the server-only `ANALYTICS_INGEST_URL` using `ANALYTICS_INGEST_TOKEN`. The exact document query `?measurement_qa=1` adds the boolean `qa:true`; the collector classifies that input as the fixed `measurement_qa` custom event rather than a normal page observation. `page_visible` and `page_engaged` send the same bounded visitor context, public path and fixed event name, with no interaction details or persistent identifier. Every collector delivery follows producer contract `p0s-ingest-2-20261028`: a fresh random 128-bit event ID per event, never derived from a visitor, page, cookie or time, and at most one retry with the same ID, only after a transport failure, timeout or 5xx. The collector forwards that retry only when the first attempt provably never reached its store and keeps event IDs only briefly in memory, so a retry cannot be counted twice but can be lost. Collection-stage reports (`bootstrap` and the GA outcomes below) carry no visitor, page or action data, follow every privacy and bot gate, and have no refusal or consent counterpart. The gateway discards raw IP and user-agent after device/session derivation, retains country and page-request/event data and the bounded public action context above in live analytics for 13 months, and expires encrypted operational backup copies within 30 days after live removal. It keeps this site linked to its own analytics property without cross-site or account identity. Events are best-effort and cannot affect the page or comparison when the collector is unavailable.
- When `GA4_ENABLED=true` and the Measurement ID and API secret are configured, the browser tag sends one `page_view` through the configured first-party `/sitedelivery/` gateway after the privacy-gated `/analytics/ga-config` request succeeds. An eligible HTML `GET` never sends GA `site_open`, creates a GA identity, or sets a GA cookie. The consented config request creates a host-only, HttpOnly first-party client ID cookie for up to 30 days; the 30-minute session cookie is set only after the tag reports its actual session ID to the same-origin, bodyless `/analytics/ga-session` route. The API secret remains Worker-only. Server `compare_open` and `product_outbound_click` events reach GA only when both stored client and verified session IDs exist; without that handshake, the same permitted action can still reach first-party Umami while GA receives no server action. Each permitted non-QA server action reports one stage to the first-party collector: `ga_skip_no_session` when no valid stored client and session exist (no substitute identity is created), otherwise the single send's `ga_ok` (2xx), `ga_fail_definite` (3xx/4xx) or `ga_fail_uncertain` (timeout, network error or 5xx). A successful HTTP response from Measurement Protocol is receipt, not processing proof. For the exact query `?measurement_qa=1`, the browser sends `measurement_qa` instead of `page_view` and uses only the fixed `traffic_type:'internal'` and `debug_mode:true` QA settings; Google's own automatic tag events for that page can still reach GA under the internal label. Google advertising signals and personalization stay disabled. QA is not claimed to be excluded from GA reports while the internal filter remains in Testing.
- `/privacy/` offers plain HTML same-origin POST forms for `/analytics/opt-out` and `/analytics/opt-in`. The edge saves the host-only, HttpOnly versioned Allow choice for 180 days or an opt-out for one year after a valid same-origin action. A minimal regional banner offers equally visible Allow analytics and No thanks buttons; the footer Privacy link always exposes both choices. The module stops current collection before opt-out, clears late Google cookies after saving, then reloads the current URL; plain HTML forms remain usable without JavaScript. Chinese and German forms carry an allowlisted `lang` (`zh`, `de`) so the saved-choice confirmation and its return link keep the page language with or without JavaScript. The edge expires consent, GA IDs and Google tag cookies on opt-out and on excluded document/config responses containing residual identifiers. DNT, Sec-GPC and opt-out suppress both analytics streams. The disclosure describes eligible page requests, comparison opens, product-link activations, visible pages, foreground interactions, technical delivery counts and estimated sessions as approximate activity, not people, verified humans, downloads, conversions or purchases. Native-app telemetry is unchanged.
- GA delivery diagnostics contain only a fixed event name, HTTP status, and receipt/rejection/network/timeout outcome. They never contain credentials, collector URLs, payloads, visitor IDs, page paths, request headers, or raw exception messages. HTTP receipt remains distinct from GA processing proof. Delivery and logging failures cannot affect the page, and failed sends are not automatically retried because an ambiguous retry could duplicate an event.
- Error documents omit the browser analytics module and its eligibility marker. The edge adds `data-analytics-allowed="true"` only to eligible documents that pass consent, privacy, bot and prefetch gates. The first-party engagement module initializes independently of the Google loader and sends each of its signals at most once per document, without storing a new identifier or interaction details. The GA browser module initializes at most once per document. HTML CSP blocks Cloudflare's automatically injected gateway-root bootstrap, preventing it from reading consent before the site. The GA module queues all-denied defaults before its asynchronous config request, grants analytics only after a permitted response, then loads or reuses its nonce-bearing `/sitedelivery/` library. Each permitted HTML response generates a fresh nonce for only the site theme and GA module; injected gateway commands and bootstrap are not authorized. Advertising storage, user data and personalization remain denied; no Google library or cookieless ping is permitted before Allow in prior-choice regions. Enhanced Measurement may collect the fixed 90-percent scroll event; automatic history page views, site search, outbound clicks, forms, video and file-download measurement remain disabled. Reporting compares Umami page requests with GA `page_view` on complete UTC days after the final setup change and processing delay; `page_visible` and `page_engaged` are separate events, and missing browser measurement is not labelled an adblock rate.
- After the privacy-gated config succeeds, the browser uses stable query-parameter ordering only for string URLs to the exact same-origin `/sitedelivery/ga/g/c` endpoint with protocol version 2 and the configured Measurement ID. Fetch and beacon bodies, options, results and parameter values (including repeated-key order) remain unchanged. Other paths, origins, tag IDs and non-string requests pass through unchanged; this adds no retry or event.
- GA, Umami page/comparison and product-action collector requests use Workers-supported manual redirect handling. A redirect is rejected as an unsuccessful delivery; credentials and payloads are never forwarded to its destination.

## Geometry comparison tool

`/geometry/`, `/zh/geometry/` and `/de/geometry/` compare exact recorded frame sizes, or manually entered stack/reach, on one coordinate scale. The homepage catalog and inline comparison remain the main buying surface. Geometry results link to existing model evidence, prices, catalog comparison and build planning.

Derive the library from all published platforms with numeric stack/reach in millimeters and attributable geometry sources. Deduplicate shared platforms without discarding their build links. Never parse presentation-only text into numbers. Withhold unresolved geometry tables from calculations and similar-size search; preserve and link their original model tables. Missing secondary dimensions remain unknown.

Each recorded size is a radio chip showing its literal stack/reach. The plot is a close-up of head-tube positions on one millimetre scale for both axes, with each selected model's recorded sizes drawn as a ladder; its dots are pointer shortcuts to recorded sizes, while the chips remain the keyboard path. The comparison adds recorded head tube, standover, front centre and fork offset rows only when A or B records them, and a glossary with a generic, project-drawn frame explains each measurement without personal-fit advice. Tolerance presets (±5, ±10, ±15, ±25 mm) set the nearby-search tolerance. Nearby sizes must satisfy separate stack and reach tolerances (0–100 mm) and the selected category. Sort by Euclidean stack/reach distance in millimeters, with deterministic ties. Label this as dimensional similarity, never a fit score, personal size recommendation, stock claim or compatibility conclusion.

Explicit URL state contains both model/size selections, manual dimensions, category and tolerance. It survives reload, language changes and browser Back/Forward. Incomplete or unavailable selections remain visible and suppress calculations; do not silently replace them. Manual dimensions are not persisted in a profile or sent in analytics. Without JavaScript, show a labeled sourced example and a complete readable size library with editing disabled.

## 7. Acceptance criteria

Every change must preserve valid cross-references and pass:

```bash
npm run check
```

For UI changes, inspect desktop and mobile behavior, keyboard access, popovers, image-failure handling, video fallbacks, filters, and production-root routing. Add or update focused tests for behavior changes. Do not add dependencies or top-level pages without a clear need and maintainer sign-off.

The static build enforces a documented homepage HTML/DOM budget so catalog growth cannot silently degrade the primary route. The 2026-10-24 Taobao/Tmall-sweep build measures 849,888 HTML bytes and 8,326 elements with 311 catalog rows; it is capped at 890,000 bytes and 8,650 elements, about 16 further rows of headroom at the measured ~2.0 KB and ~20 elements per added row. The previous 830,000-byte / 8,050-element cap (2026-10-24 Girder range, 790,115 bytes and 7,742 elements at 284 rows) was exceeded by the KUNG range and the sweep's nineteen listing-priced candidates; before it, the 750,000-byte / 7,400-element cap (2026-10-03, 712,514 bytes and 7,154 elements at 263 rows) was raised only after the expanded Girder catalog exceeded it, and per-row duplicated attributes were too small to recover the overage without changing sort and filter scripts. The cap is fixed, so further catalog growth again requires a measured review. Nine browser cases across English, Chinese and German at 1,600, 390 and 320 px show no document or price-cell overflow at each cap (`docs/homepage-budget-browser-2026-10-24.md`). Desktop and mobile browser checks are required when this baseline changes. Budget changes require a measured browser rationale.

Research bundles are evidence inputs, not publication authority. A dated marketplace snapshot may support an exact price observation, but a price is attachable only to the exact variant it identifies. Split or ambiguous trims remain candidates. Raw captures stay local; selected source-attributed images may become public data assets only through the media and privacy contract above.

## 8. Information-retention contract

- `data/coverage-baseline.json` is a monotonic, machine-generated inventory of accepted record identities, populated evidence fields, record relationships, price coverage, and image quality.
- Run `npm run coverage:accept` after adding catalog information. The command may add protection or raise its minimum quality, but it must never erase an accepted identity, field, relationship, price target, or image-quality level.
- `npm run coverage:check` fails when accepted information disappears, an image becomes less exact or loses its protected source or hosting quality, an active bike loses its primary image or price coverage, or new information has not yet been added to the baseline.
- Correct a materially wrong record by adding the supported replacement and documenting the old identity in `data/retired-records/`. Each retirement needs a reason, active evidence, review date, and an active replacement when one exists.
- Retirement records authorize only the named identity removal. They do not authorize an active bike to lose protected price, evidence, fact, or image coverage.
- A scoped `source-type` retirement may correct a disproven publisher classification for one active source. It must name the protected tier, exact corrected type, evidence and review date; the source retains classification history and an authority note. The baseline keeps its historical floor. This exception does not relax source links, reliability dimensions, image quality or any other record protection.
- CI publishes a before-and-after coverage report for review. Baseline, retirement, and guard changes require code-owner review on branches where GitHub branch protection enforces CODEOWNERS.

Tire compatibility uses validated maximums separately from fitted or stock widths. Per-drivetrain limits may be null when unknown; a missing layout or conflicting shell never confirms fit. Exact manufacturer shifting restrictions and revision conflicts remain visible, and conservative warning thresholds do not resolve those conflicts.

Planner frame weights retain the basis of the numeric default, including the conservative maximum across recorded sizes/finishes; different example claims are labeled separately. Package overlap advice uses source-attributed included/excluded/optional/unknown lists, never keyword presence in prose. Unknown and optional parts cannot reduce the allowance as included components.

Retain literal conflicting manufacturer geometry as source material. A source-inconsistent geometry record must mark derived_fit_eligible false and show its warning; affected cells cannot supply a derived fit conclusion. Current size/travel claims retain separate prior observations and do not assert historical revisions were false. Fork/caliper exceptions remain exact-model and exact-fork scoped.

Frame-fact search includes recorded material and standards in both catalog stages. Inline and expanded comparisons use native table rows/cells with scoped column and row headers; column order, scrolling, and share state remain functional. Completed geometry transcription flags retain source-unit and independent-measurement uncertainties.

The published build-cost guide includes a source-dated four-model cost-basis reference and a downloadable CSV generated from the same candidate prices and existing reviewed frameset allowance. Complete-bike prices receive no build allowance. Missing frame prices and overseas delivered costs remain unknown in HTML and blank in CSV; no tax rate, compatible bill of materials, delivered quote or new price observation is inferred. Article publication dates and source observation dates remain distinct.
