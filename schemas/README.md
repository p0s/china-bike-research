# Published schemas

These JSON Schema files describe the main public JSON record types for editors and external tools, including product-image, curated-video, and atomic research-attempt records. The executable validator in `src/lib/data.mjs` adds cross-reference, uniqueness, date, range, local-file, image-rights, video-target, source, price-history, and search-exhaustion checks that JSON Schema alone does not cover.

Image and video schemas use [JSON Schema draft 2020-12](https://json-schema.org/draft/2020-12/schema). Image records cover primary/gallery roles, strict local responsive manifests, hidden historical remote references, review/extraction metadata and dated corrections. Sourced derivatives require their rights, editorial and privacy records, with separate product-photo and public-post/listing byte budgets. The no-license flag is mandatory for product-photo and historical remote-quotation contracts; existing local public-post/listing records retain their source-attribution and rights notes.

Video provider branches require YouTube IDs/channel URLs or canonical XHS post IDs and immutable capture-archive digests. XHS records cannot contain YouTube IDs or chapter/player metadata and remain research-only. Target type determines the exact-platform, exact-variant or exact-model-lead match. The executable validator still compares URLs to sibling IDs, disclosure links to XHS posts, detail paths to manifests, source/variant references, archive identity and file existence; JSON Schema cannot express those cross-record and sibling-value comparisons alone.

For complete standards validation, run `node scripts/check-media-schemas.mjs` with an existing Ajv draft-2020 module resolvable as `ajv/dist/2020.js`, or select it with `MEDIA_SCHEMA_VALIDATOR_MODULE`. This read-only check validates every image/video record and adversarial fixtures, then verifies the sibling comparisons still rejected by the executable contract. It does not install a dependency. The normal dependency-free test suite checks all current media field names against strict declared object boundaries and guards the provider/privacy/budget contracts.
